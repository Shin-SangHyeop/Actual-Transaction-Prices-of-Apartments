# 아파트 전월세 실거래가 API 기술문서 분석

분석 대상: `아파트 전월세 실거래가 자료 기술문서.hwp`

## 문서에서 확인한 API 규격

- 서비스: 국토교통부 아파트 전월세 실거래가 상세 자료
- 요청: REST GET, XML
- 기본 URL: `apis.data.go.kr/1613000/RTMSDataSvcAptRent`
- 기능 경로: `/getRTMSDataSvcAptRent`
- 필수 입력: `serviceKey`(URL 인코딩), `LAWD_CD`(법정동 코드 앞 5자리), `DEAL_YMD`(계약연월 6자리)
- 페이지 값 `pageNo`, `numOfRows`는 문서상 선택 항목이며 앱은 페이지 조회를 위해 이를 전달한다.
- 응답 상태는 `resultCode`, `resultMsg`에 들어간다. 정상 예시는 코드 `000`, 메시지 `OK`다.
- 주요 거래 항목: `aptNm`, `dealYear`, `dealMonth`, `dealDay`, `deposit`(만원), `monthlyRent`(만원), `excluUseAr`, `floor`, `buildYear` 등.
- 오류표에는 자료 없음 `03`, 서비스 접근 거부 `20`, 잘못된 서비스 키 `30`, 키 만료 `31` 등이 기재돼 있다. 서비스 접근 거부 시 활용 신청 승인 상태를 확인하도록 안내한다.

## 앱 구현과 대조한 결과

- 앱의 매매 및 전월세 URL, 지역 코드와 계약월 파라미터, XML 응답 파싱, 페이지 번호 처리는 문서의 인터페이스와 일치한다.
- 앱은 현재 날짜로부터 역순으로 조회월을 계산해 `DEAL_YMD`에 전달한다.
- 전월세 보증금 이름이 문서의 `deposit`인데 기존 파서에 이 별칭이 누락되어 있었다. 파서에 `deposit`을 추가했다.
- 문서상 결과 코드 `03`은 자료 없음이므로 앱에서 빈 결과(0건)로 처리하도록 변경했다. 기타 비정상 응답은 오류로 표시한다.
- `serviceKey`는 설정 파일에 URL 디코딩된 값으로 보관하고 `urlencode`로 요청 URL에 인코딩한다. 문서의 URL Encode 요구를 충족한다.

## 검증 및 현재 제한

- 문서 필드를 사용하는 전월세 보증금 파싱 및 자료 없음 처리 테스트를 추가했다.
- 최종 자동 회귀 테스트: 12/12 통과. Python 문법 검사 통과.
- 현재 키로 실제 요청을 시도했으나 HTTP 403이 반환됐다. 이 응답은 이 실행 환경에서 서비스 사용이 아직 확인되지 않았다는 뜻이다. 포털의 해당 API 활용 신청/승인 상태와 키 상태를 확인한 뒤 실제 조회를 재검증해야 한다.
- 이 문서 분석만으로는 관심 단지/법정동 코드가 정해지지 않으므로 실제 관심 아파트 조회는 아직 수행하지 않았다.

## 키 권한 실측 (2026-10-11)

같은 저장 키로 실 API를 비교했다. 전월세는 HTTP 200, `000 / OK`였고 앱 파서로 이번 달 종로구 전체 15건을 읽었다. 매매는 HTTP 403과 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` / 반환 코드 `30`을 반환했다. 따라서 키 형식 자체보다는 매매 API의 활용 신청/승인 또는 해당 서비스에 키가 연결된 상태를 확인해야 한다. 앱은 이 상황을 안내하고 예외 문자열에 요청 URL(키 포함 가능)이 노출되지 않게 처리한다.
